# نظام إدارة مكتبة الملازم الدراسية — المراحل 1 إلى 5 (نسخة كاملة أولى)

**المرحلة 1**: هيكل المشروع، تصميم قاعدة البيانات، نظام تسجيل الدخول والصلاحيات (Admin/Teacher).
**المرحلة 2**: واجهة الطالب الكاملة (الرئيسية، تصفح+فلترة، تفاصيل الملزمة، نموذج الطلب) بهوية بصرية مخصصة.
**المرحلة 3**: لوحة تحكم الأدمن الكاملة (الأساتذة، الملازم، الطلبات، المواد والمراحل).
**المرحلة 4**: لوحة تحكم الأستاذ (إحصائياته وطلباته فقط، بفلترة صارمة).
**المرحلة 5**: التقارير المالية التفصيلية + الإشعارات داخل لوحة الإدارة.

## خطوات التشغيل (على جهازك، مرة واحدة)

### 1. المتطلبات
- Node.js 18 أو أحدث
- حساب قاعدة بيانات PostgreSQL مجاني (الأسهل: [neon.tech](https://neon.tech) أو [supabase.com](https://supabase.com))

### 2. تثبيت المكتبات
```bash
npm install
```

### 3. إعداد متغيرات البيئة
انسخ `.env.example` إلى ملف جديد باسم `.env` واملأ القيم:
```bash
cp .env.example .env
```
- الصق رابط قاعدة البيانات في `DATABASE_URL`
- ولّد مفتاح NEXTAUTH_SECRET عبر: `openssl rand -base64 32`

### 4. إنشاء الجداول في قاعدة البيانات
```bash
npm run prisma:migrate
```
سيطلب منك اسمًا للـ migration، اكتب مثلًا: `init`

### 5. تعبئة البيانات الأولية (حساب الأدمن + بيانات أساسية)
```bash
npm run seed
```
سيظهر لك في الطرفية اسم المستخدم وكلمة المرور لحساب الأدمن — **غيّرها فورًا بعد أول دخول**.

### 6. تشغيل المشروع
```bash
npm run dev
```
افتح `http://localhost:3000`

## المرحلة 2 — واجهة الطالب (مكتملة)
- `/` الصفحة الرئيسية: بحث، تصنيفات حسب المرحلة، الأكثر طلبًا، أحدث الملازم
- `/booklets` تصفح كامل مع فلترة حسب المادة/المرحلة/الأستاذ + بحث نصي
- `/booklets/[id]` تفاصيل الملزمة + نموذج طلب من خطوة واحدة (بدون تسجيل دخول)
- `POST /api/orders` يحفظ الطلب، ينسخ السعر ومعرّف الأستاذ وقت الطلب، وينشئ إشعارًا للأدمن

**الهوية البصرية**: مستوحاة من الدفتر نفسه — حافة "تجليد حلزوني" (`notebook-edge`) على كل بطاقة ملزمة كعنصر مميز، وتسطير بأسلوب الهايلايتر (`marker-underline`) للعناوين المهمة، بخطين عربيين: **El Messiri** للعناوين و **Tajawal** للنصوص. الألوان: كحلي "الحبر" (`ink`) كلون أساسي، وبرتقالي "الهايلايتر" (`marker`) للأزرار الرئيسية.

**قرار تصميم مهم**: لا تُحسب أرباح الأستاذ عند مجرد استلام الطلب — الحساب سيتم فقط عند تأكيد التسليم فعليًا (مرحلة إدارة الطلبات القادمة)، حتى تبقى الأرقام المالية دقيقة.

## المرحلة 4 — لوحة تحكم الأستاذ (مكتملة)
سجّل الدخول عبر `/login` بحساب أستاذ أنشأته من `/admin/teachers/new`.

- `/teacher/dashboard` إحصائيات عامة: عدد ملازمه، إجمالي الطلبات، النسخ المباعة فعليًا (طلبات "تم التسليم")، أرباحه الحالية، رسم بياني لأرباحه الشهرية خلال السنة الحالية، إحصائيات سنوية، وآخر طلب
- `/teacher/booklets` أداء كل ملزمة على حدة: عدد الطلبات، النسخ المباعة، إجمالي الإيرادات، أرباحه منها، وتاريخ آخر طلب
- `/teacher/orders` كل الطلبات الواردة على ملازمه فقط (عرض بدون تعديل الحالة، فهذا صلاحية الأدمن)

**الضمان الأمني الجوهري**: كل صفحة في لوحة الأستاذ تمرّ عبر `lib/teacherSession.ts`، الذي يقرأ `teacherId` من الجلسة الموقّعة فقط — لا من الرابط ولا من أي مدخل يتحكم به المستخدم. هذا يمنع فعليًا أي أستاذ من رؤية بيانات أستاذ آخر، حتى لو حاول تعديل الرابط يدويًا.

## المرحلة 5 — التقارير والإشعارات (مكتملة)
- `/admin/reports` تقارير مالية بفلترة زمنية (اليوم / آخر 7 أيام / هذا الشهر / هذه السنة / كل الفترات): إجمالي الإيرادات، حصة المكتبة، حصص الأساتذة، عدد النسخ المباعة، رسم بياني شهري، وجدول أداء تفصيلي لكل أستاذ
- جرس إشعارات في أعلى لوحة الأدمن: عداد غير المقروء، قائمة منسدلة، تعليم كمقروء (فردي أو الكل). يظهر إشعار تلقائيًا مع كل طلب جديد من الطالب (مبني مسبقًا من المرحلة 2)

**ملاحظة مهمة**: كل أرقام التقارير مبنية على `ProfitSnapshot` فقط، أي الطلبات التي وصلت فعليًا لحالة "تم التسليم" — وليس كل الطلبات الواردة. هذا امتداد مباشر لقرار "لقطة الأرباح" الذي اتخذناه من المرحلة 3، ويضمن أن الأرقام المالية التي يراها صاحب المكتبة والأساتذة دقيقة وليست تقديرية.

## تحسينات مستقبلية اختيارية (غير أساسية)
- ربط الإشعارات بواتساب/تيليجرام (مذكور في الخطة الأولى كـ"مستقبلًا")
- رفع صور الغلاف مباشرة (بدل رابط URL) عبر Cloudflare R2 أو S3
- تصدير التقارير كملف Excel/PDF
- دعم أكثر من محافظة فعليًا عند توسع المكتبة (البنية جاهزة لذلك مسبقًا)

## المرحلة 3 — لوحة تحكم الأدمن (مكتملة)
سجّل الدخول عبر `/login` بحساب الأدمن الذي أنشأه `npm run seed` (راجع الطرفية للحصول عليه، أو استخدم القيم في `.env`).

- `/admin` نظرة عامة: أساتذة نشطون، عدد الملازم، طلبات جديدة، إجمالي الإيرادات المكتملة، آخر الطلبات
- `/admin/teachers` إنشاء حسابات الأساتذة (اسم مستخدم + كلمة مرور)، تعديل بياناتهم ونسبة أرباحهم، تعطيل/تفعيل، حذف (محمي إذا كان له ملازم)
- `/admin/booklets` إضافة/تعديل/حذف الملازم، ربطها بأستاذ ومادة ومرحلة، تحديد نسبة ربح مخصصة لكل ملزمة (تتجاوز نسبة الأستاذ الافتراضية)، إظهار/إخفاء
- `/admin/orders` كل الطلبات مع فلترة بالحالة، وتغيير الحالة فوريًا من قائمة منسدلة
- `/admin/catalog` إدارة المواد والمراحل الدراسية (تُستخدم عند إضافة أي ملزمة)

**نقطة تصميم جوهرية**: عند تغيير حالة أي طلب إلى "تم التسليم"، يُحسب وتُحفظ لقطة الأرباح (`ProfitSnapshot`) تلقائيًا بنسبة الأستاذ وقتها بالضبط. إذا رجعت الحالة للخلف لاحقًا، تُحذف اللقطة تلقائيًا — هذا ما يضمن دقة تقارير الأرباح في المرحلة القادمة.

كل إجراءات لوحة الأدمن (`app/admin/actions.ts`) تتحقق من صلاحية الأدمن بنفسها من جديد، ولا تعتمد فقط على حماية الـ middleware — هذا هو خط الدفاع الحقيقي.
